## 二、红外发射（IR blaster）

### 硬件

红外 LED 挂在 **SPI1**（QUP `0x884000`），引脚 GPIO114–117。

### 三个坑

1. **compatible 名字**：主线 `ir-spi` 驱动要的是 `ir-spi-led`，不是原厂的 `ir-spi`；
2. **电源**：必须提供名为 `irda_regulator` 的稳压器；
3. **QUP 父节点**：只开 `spi1` 没用，必须同时把 `qupv3_id_0`（`geniqup@8c0000`）设为 okay；
4. **内核配置**：`CONFIG_LIRC` 是 bool → 需要 `RC_CORE=y` → 需要 `MEDIA_SUPPORT=y`，
   所以 media 核心改成内建，其余驱动仍是模块。

### 验证

```
/dev/lirc0
ir-ctl -d /dev/lirc0 --scancode nec:0x20df10ef   → rc=0
```

## 三、NFC（NXP NQ）

### 硬件

`nq@28` 在 **i2c9**（QUP `0xa84000`），IRQ=GPIO47、VEN=GPIO103、FIRM=GPIO48。

### 坑

- **`qupv3_id_1` 父节点**必须 okay（同 IR）；
- **`gpi_dma1`** 必须是 okay，否则 `geni_i2c` 报
  `Failed to get tx DMA ch` 并 defer；
- 模块链：`nfc.ko → nci.ko → nxp-nci.ko → nxp-nci_i2c.ko`。

### 验证

```
/sys/bus/i2c/devices/0-0028/driver -> nxp-nci_i2c
/sys/class/nfc/nfc0
```

## 五、音频（当天的主战场）

主板用 **WCD9340（原厂名 tavil）**，音频接口 SLIMbus。

### 5.1 八道墙，逐条攻破

| # | 障碍 | 解法 |
|---|---|---|
| 1 | `q6asm_dai` 被 cmdline + payload 双重黑名单 | 删除两处 |
| 2 | `q6asmdai` 缺 `dai@N` 子节点 | DT 补上（否则 `No dais found in DT`） |
| 3 | `audio-routing` 用了 vendor 私有 widget 名 | 换成主线 WCD9340 的 `AMIC`/`DMIC`/`MIC BIAS` |
| 4 | FE→BE 没有路由 | `amixer cset name='SLIMBUS_0_RX Audio Mixer MultiMedia1' 1` |
| 5 | **SLIMbus AFE 口配置被 DSP 拒绝** | 见 5.2（主线两个 bug） |
| 6 | **q6asm 缓冲区内存映射失败** | 连续映射失败 → 自动按 period 分段映射 |
| 7 | 扬声器功放（WSA881x）枚举成功但寄存器读不了 | 暂时摘除，见 5.4 |
| 8 | 录音全是 0 | 见 5.5，定位到 SoC 侧 SLIMbus 接收方向 |

### 5.2 主线两个真 bug（已在 `wip/audio/` 保存改动文件）

**bug 1：`q6afe_slim_port_prepare()` 从来没有设置 `slimbus_dev_id`**
—— `struct q6afe_slim_cfg` 里根本没有这个字段，SM8150 固件要求
`AFE_SLIMBUS_DEVICE_1 = 1`。

**bug 2：`shared_ch_mapping` 号段**
—— AFE API 注释写明是「128..255 的共享通道 ID」，主线填的是 0。

改完后 `AFE enable for port 0x4000` 不再报错。

### 5.3 q6asm 内存映射

症状：

```
qcom-q6asm: DSP returned error[1]
q6asm-dai: Memory_map_regions failed
```

排查过程：

- `mem_pool_id = 3`（SHMEM8_4K）正确 —— 试了 0–9，只有 3 和 4 被识别；
- SID 无关 —— 试了 -1/0/1/2/3/0x21/8211，错误一样；
- 顺序无关 —— 把 memory map 挪到 `open_write` 之后无效；
- **缓冲区大小有关**：64 KB 成功，128 KB 以上失败；
- 分段映射（`is_contiguous=0`）后 512 KB 也能成功。

最终实现：`q6asm_map_memory_regions()` 连续映射失败时自动退化为按 period 分段映射。
改完后 `aplay` 2 秒 440Hz 跑完、dmesg 干净。

### 5.4 扬声器功放（WSA881x）

- 两个功放在 SoundWire 上**枚举成功**：`sdw:0:0:0217:2010:00:1` / `:2`；
- 但寄存器读写全部失败：`trf on Slave 0 failed:-5`、`SWR CMD error`；
- 把功放加进 BE 的 codec 列表会让播放超时（-ETIMEDOUT），所以已摘除；
- fifo 状态 `0x3e000127` 解码 = `NEW_SLAVE_ATTACHED | CHANGE_ENUM_SLAVE_STATUS |
  SLAVE_PEND_IRQ | RD_FIFO_UNDERFLOW`。

### 5.5 决定性实验：codec 内部环回

把采集源设成 codec 内部的 `RX_MIX_TX0`（播放混音 → 采集口），同时播放 440 Hz：

```
内部环回录音 -> RMS 0  峰值 0
```

而 codec 的 SLIM TX 端口寄存器确认已使能（`0x50 = 0x05`）。

**结论：SoC 侧 SLIMbus 接收方向（ADSP AFE 从总线取数据）没有工作**，
与麦克风、与通道基址（0/16/32/128 全试过）都无关。

### 5.6 端口编号的坑

```c
#define SLIMBUS_0_RX  2
#define SLIMBUS_0_TX  3
#define SLIMBUS_1_RX  4
```

编号是**交错**的！不能用区间判断方向，要按奇偶。
（这个错误一度让 TX 通道基址参数完全失效。）

### 5.7 顺手做的工具

`mi9-audio`（`payload/usr/local/bin/`）：

```sh
mi9-audio setup       # 只配置路由
mi9-audio tone 2      # 播 2 秒 440Hz
mi9-audio play f.raw  # 播放 raw PCM
mi9-audio status
```

## 六、工程上的坑

### `make modules` 不会删除「由 =m 改成 =y」的旧 .ko

`CONFIG_RC_CORE` 从 `=m` 改成 `=y` 后，编译树里的旧 `rc-core.ko` 仍然存在，
跟着 payload 进了系统，导致 `modprobe ir-spi` 报 `Exec format error`
（而 `insmod` 正常——这个差异是突破口）。

★ 以后任何 `=m → =y` 的变更，都要顺手删掉旧的 `.ko`。

### 板级 DTS 会被重建冲掉

`apply-dts*.sh` 每次构建都会覆盖板级 DTS。
所有改动放在 `dts/cepheus-cam-ir-nfc.dtsi`，由 `apply-dts5.sh` 自动追加。
