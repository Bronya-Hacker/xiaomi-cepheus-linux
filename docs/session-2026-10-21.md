## 一、最大的发现：功放是 CS35L41，不是 WSA881x

之前几个小时都在折腾 codec 内部 SoundWire 上的 WSA881x（寄存器读不出来）。
挂载原厂 vendor 分区（`/dev/sde53`，只读）后一眼看到：

```
/vendor/firmware/cs35l41-dsp1-spk-prot.{bin,wmfw}
/vendor/lib/modules/audio_cs35l41.ko
原厂 DT: cs35l41@40 { compatible = "cirrus,cs35l41"; }  在 i2c@890000
```

**主线本来就有 cs35l41 驱动**，而且我们配置里一直是 `=m`。

### 接线

| 信号 | 值 |
|---|---|
| I2C | `i2c@890000`（主线 i2c4），地址 **0x40** |
| 复位 | GPIO **89**（主线驱动要求**高有效**） |
| 中断 | GPIO **10**（低电平） |
| 音频输入 | **secondary MI2S**：GPIO126(SCLK) 127(WS) 128/129(SD) 130(MCLK) |

### 踩的坑：复位极性

第一版照原厂语义写 `GPIO_ACTIVE_LOW`，驱动报
`Failed waiting for OTP_BOOT_DONE (-ENXIO)`。
主线驱动是先拉低 2ms 再拉高释放（假设高有效），用 ACTIVE_LOW 等于
**一直按着复位**。改成 `GPIO_ACTIVE_HIGH` 后立刻成功：

```
cs35l41 0-0040: Cirrus Logic CS35L41 (35a40), Revision: B0
```

## 二、声卡起不来的真凶：q6asm_dai 被自己 blacklist 了

现象：

```
platform sound: deferred probe pending: snd-sm8150: MultiMedia1:
                error getting cpu dai name
```

查了很久 DTB，其实 DTB 完全没问题。真因是
`/etc/modprobe.d/blacklist-audio.conf` 里有一行 `blacklist q6asm_dai`
—— 是 10-18 为了"内核报错清零"加的（当时 DTS 里确实没有 dais 子节点）。

去掉后 `modprobe q6asm_dai` 一加载，声卡立刻注册，**1032 个控件**全出来。

已做成 `payload/etc/modules-load.d/mi9-audio.conf` 显式按依赖顺序加载整条链，
并把 `blacklist-audio.conf` 换成"只解释、不屏蔽"的版本。

## 三、红外：陈旧的 rc-core.ko

`modprobe ir-spi` 报 `Exec format error`，但 `insmod` 同一个文件能成功。
原因是 `RC_CORE` 从 `=m` 改成 `=y` 之后，**旧的 `rc-core.ko` 还躺在
`/usr/lib/modules` 里**，modprobe 会先 insmod 它。tar 解压只覆盖同名文件、
不删多余文件，所以它永远消失不了。

修复：initramfs 解压 mods 之前先
`rm -rf /usr/lib/modules/<kver>`，彻底清掉陈旧模块。

## 四、变砖三连：**不能去掉 126-129 的保留**

为了把 secondary MI2S 的 126-129 让给功放，我把板级 DTS 里的

```dts
gpio-reserved-ranges = <0 4>, <126 4>;
```

改成了 `<0 4>`。结果**刷进去直接起不来**（不进 fastboot、没网络、没串口输出）。

**受控 A/B 验证**（同一次 kernelfat，只换 boot）：

| boot 里的保留 | 结果 |
|---|---|
| `<0 4>, <126 4>`（原样） | ✅ 正常启动 |
| `<0 4>`（去掉 126-129） | ❌ 起不来 |

主线所有 sm8150 板子（mtp / hdk / surface-duo / oneplus / sony）都写着 `<126 4>`，
说明这 4 个脚**在硬件上被别的东西占着**（大概率 UFS / 电源相关）。

**所以扬声器走 secondary MI2S 这条路，在"保留不能动"的前提下走不通。**
要继续攻，得先搞清这 4 个脚到底被谁用。

## 五、三个让修复"静默失效"的构建 bug

这三个是今晚最坑的，因为**表面上看不出错**：

1. **02 从不重打 `wifi-cfg.tar.gz`**，只拷贝 `out/` 里现成的包。
   于是改了 `payload/` → 版本号（按 payload 源码算的指纹）变了，但包还是旧的。
   设备看到"新版本"→ 重新解压 → 解压出**旧文件**。
   → 现在 02 发现 `payload/` 比 tar 新就自动重跑 05。

2. **05 的暂存目录在 `/mnt/c` 上**（Windows 挂载），那里 `chmod` 无效，
   目录永远 0777 → tar 里 `./` 是 `drwxrwxrwx` → 解压后手机 `/` 会变 0777
   （SSH 全废）。05 自己的权限回归测试拦住了这次。
   → 暂存目录改到 `/tmp/mi9-payload-stage`（Linux 本地）。

3. **05 的可执行位白名单只匹配 `*.sh`**，不带后缀的脚本被打成 644：
   `mi9-audio: Permission denied`、`mi9-audio-setup.service` 每次开机失败。
   → 现在 `usr/sbin`、`usr/local/{sbin,bin}` 整个目录一律 755。

## 七、下次接着干什么

1. **扬声器**：查清 GPIO126-129 到底被谁占用（UFS？电源？）。
   线索：原厂 vendor DT 里它们就是 `function = "sec_mi2s"`，
   但主线 sm8150 **所有**板子都保留它们 —— 大概率是 Qualcomm 参考设计里
   给 UFS/PMIC 预留的。若确实冲突，扬声器在主线可能永远出不了声，
   除非换硬件路径（例如确认功放是否有模拟输入）。
2. **SLIMbus 数据面**：录音全 0（播放通路正常）——这是音频剩下的另一个坑。
3. **NFC**：SN100U 需要移植驱动，工作量与相机同级。
